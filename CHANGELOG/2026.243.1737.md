# 2026.243.1737 — fix: advance PFX_SHA to the pixelflux commit that fixes nested compositors

## Summary

Advances `PFX_SHA` to `2e79a415`, the merged `opencharly/pixelflux#3`, and bumps the candy version
from `2026.243.0120` to `2026.243.1659`. Two lines, both accounted for here.

`check-selkies-labwc-pod` has been red because **no nested compositor could run under pixelflux at
all**:

```
xdg_wm_base#8: error 4: wrong configure serial: 21
labwc: wlr_backend_finish: Assertion failed (core dumped)
```

pixelflux sent xdg configure serials **non-monotonically** — 22, then 20, then 21 — because its
`XdgDecorationHandler` called `send_configure()` before the initial configure. Smithay's
`ack_configure` drops every pending configure up to the acked serial, so acking 22 discarded 20
and 21 and the next ack matched nothing. The client was blameless, and chrome's FATAL was
downstream of labwc rather than a second fault.

`pixelflux#3` fixes it the way Smithay's own anvil does: `new_decoration` sends nothing, and
`request_mode` / `unset_mode` guard on `is_initial_configure_sent()`.

## Why the total warning count is not the number to read

The same run reports `warnings: 326`, and every one is an artifact of how an unmerged cross-repo
change has to be gated. `CHARLY_REPO_OVERRIDE` replaces a repo with its `main`, and `main` names
newer member pins than the tag `distro-cachyos` currently pins — so charly correctly reports
`resolved to multiple versions` **once per member**, for members this diff never touches:

```
9  pod-wayvnc          9  layer-xdg-portal              9  layer-thunar
9  pod-waybar          9  layer-wl-screenshot-pixelflux 9  layer-sway-desktop
9  pod-pipewire        9  layer-wl-record-pixelflux     9  layer-python  ...
```

The count scales with the number of overrides, not the size of the change:

| overrides | warnings |
|---|---|
| 0 (baseline) | 16 |
| 1 | 38 |
| 2 | 145 |
| 3 | 326 |

A zero-warning gate and an override-based gate are mutually exclusive for a cross-repo pin change:
the only run with no override-induced skew is one that tests no unmerged code. What can be held to
zero is the class under test, and it is.

Per R4 none of this is allowlisted — silencing a skew class would hide exactly the pin drift these
changes exist to remove.
